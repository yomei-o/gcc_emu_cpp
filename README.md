# ブラウザだけで C / C++

インストールなし、送信なし。ブラウザのタブの中で、本物の gcc と g++ が動きます。

**[試す: yomei-o.github.io/gcc_emu_cpp](https://yomei-o.github.io/gcc_emu_cpp/web/)**

学生が C と C++ を学ぶための場所として作っています。プログラムを書いて、ボタンを
押すと、コンパイルされて走る。それだけのことを、何も入れずにできるように。

## 何が動いているのか

Alpine Linux の **gcc / g++ 13.2.1** — x86-64 の Linux バイナリそのもの — が、
WebAssembly にした x86-64 エミュレータの中で動いています。書いたプログラムを
コンパイルするのも、できたプログラムを実行するのも、同じエミュレータです。

ブラウザ用に作り直したコンパイラではありません。`apk` から取ってきた本物が、
`cc1` や `as` や `ld` を子プロセスとして起動しながら、そのまま動いています。

エミュレータは [x86_emu_cpp](https://github.com/yomei-o/x86_emu_cpp) です。

## できること

- **プロジェクト** — お手本から始めるか、新しく作る。ブラウザを閉じても残ります
- **アップロードとダウンロード** — ファイル単位でも、プロジェクトごと（`.tar.gz`）でも
- **CSV からグラフ** — ファイルと種類を選ぶと **JavaScript が出てきます**。
  ボタンで描画。書き換えて押せば、そのとおりに描きます
- **保存されるのは変更したファイルだけ** — お手本の中身は保存しません。
  ブラウザの保存領域は 5 MB しかないので、これをやらないと学習データひとつで足りなくなります

サブディレクトリはありません。プロジェクトはファイルが平らに並んだものです。

## お手本

| | |
| --- | --- |
| C: はじめの一歩 | printf と for 文 |
| C++: はじめの一歩 | vector, string, ラムダ式 |
| ニュートン法で sin を解く | 接線で追い込む。誤差が毎回およそ2乗で小さくなる様子を CSV に |
| Z 変換で sin を作る | 極を2つ置いた漸化式だけで正弦波が出る。ループ内で `sin()` を呼びません |
| バブルソート、収束のかたち | 残っている逆転数を測る。隣としか交換しないので**直線**に落ちます |
| クイックソート、収束のかたち | 同じ数列、同じ物差し。遠くと交換するので**階段状**に落ちます |
| MNIST を C++ だけで | ライブラリなし。IDX を読むヘッダと、2層のネットだけ |

ソートの2つは、速さではなく**整い方の形**を見るためのものです。同じ種で同じ数列を
かき混ぜ、横軸を比較回数にしてあるので、2つの CSV を重ねると違いがそのまま見えます。

## 手元で動かす

Linux か WSL が要ります。

```sh
sh tools/fetch_alpine.sh     # Alpine の gcc 一式を取ってくる
sh tools/wslpayload.sh       # ブラウザが運ぶツリーにする
sh build.sh                  # エミュレータ（ネイティブ）
sh tools/wslcheck.sh         # C と C++ をコンパイルして実行してみる
```

ブラウザ用は:

```sh
EMCC=/path/to/emcc sh web/build.sh
sh tools/wslpack.sh          # ツリーを guest/ へ
```

`web/x86emu.js` と `web/x86emu.wasm` はコミットされていて GitHub Pages がそのまま
配信します。**`web/wasm_api.cpp` か `x86_emu_cpp/src/` を変えたら、必ず建て直して
コミットし直してください** — 先週のモジュールに今週の JavaScript が話しかけると、
ソースのどこにも見えない壊れ方をします。

## 速さについて（正直なところ）

エミュレータは素の解釈実行なので、実機のおよそ100分の1です。ブラウザでの実測:

| | |
| --- | --- |
| **C のコンパイル** | **6.6 秒** |
| プログラムの実行 | 0.0〜0.3 秒 |
| **C++ のコンパイル** | **1〜2 分** |
| ツールチェーンの取得 | 57 MB、一度きり |

**C は快適で、C++ は待ちます。** 壊れているわけではないので、そのまま待ってください。

C++ が遅い理由は測ってあります。cc1plus 自体は 8 秒、前処理も 17 秒で、残りの 60 秒は
`<iostream>` や `<vector>` が展開した 808 KB のテンプレート定義を**解析**する時間です。
`<vector>` と `<algorithm>` だけでも 71 秒なので、iostream 固有の話ではなく、C++ の
標準ライブラリがそういうものだ、ということです。

プリコンパイル済みヘッダは試しました。50 秒まで縮みますが、38 MB を持ち歩くことに
なるので採用していません。

本命はエミュレータ側で、デコード結果を使い回すようにすることです。C++ を 15〜20 秒、
C を 2 秒にできる見込みで、`resume.md` に手順を書いてあります。

## ライセンスと出どころ

エミュレータは x86_emu_cpp と同じライセンスです。`guest/tree/` に入っているのは
[Alpine Linux](https://alpinelinux.org/) のパッケージから取り出したもので、
gcc, binutils, musl はそれぞれ GPL / LGPL です。`tools/fetch_alpine.sh` が
どこから何を取ってきたかを記録しています。
